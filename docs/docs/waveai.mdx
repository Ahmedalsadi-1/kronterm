KronosCode is KronTerm's local agent execution layer. KronosChamber is its primary chat and control surface. Together they
connect a request to the terminal, files, browser, sandbox, native desktop, canvas, research tools, and configured MCP
servers while keeping meaningful actions visible.

## Open KronosChamber

| Shortcut                                 | Action                   |
| ---------------------------------------- | ------------------------ |
| <Kbd k="Cmd:Shift:a" />                  | Toggle the AI panel      |
| <Kbd k="Ctrl:Shift:0" windows="Alt:0" /> | Focus the AI composer    |
| <Kbd k="Cmd:k" />                        | Start a new conversation |
| <Kbd k="Enter" />                        | Send a message           |
| <Kbd k="Shift:Enter" />                  | Insert a new line        |

KronTerm starts and monitors the local KronosCode/KronosChamber runtime. The view reports startup, connection, degraded,
and unavailable states. When startup fails, use the displayed component status and suggested recovery action instead of
repeatedly reopening the widget.

## Workspace context

KronosCode can work from the surfaces already open in the workspace:

| Surface            | Context and actions                                                         |
| ------------------ | --------------------------------------------------------------------------- |
| **Terminal**       | Scrollback, shell state, commands, running processes, exit results          |
| **Files and code** | Local or remote files, diff-reviewed edits, Monaco and LSP information      |
| **Browser**        | Structured page state, navigation, clicking, typing, scrolling, screenshots |
| **Sandbox**        | Isolated Linux desktop, terminal, editor, browser, and filesystem           |
| **macOS desktop**  | Accessibility state and permission-aware native input                       |
| **Canvas**         | Selected widgets, task lineage, approvals, evidence, and outputs            |
| **Research**       | Documentation, web search, code search, MCP servers, and skills             |

Context is scoped to the request and active surface. Host, browser, remote, desktop, and sandbox operations remain separate
execution routes.

### Canvas context

On the spatial canvas, open a widget or agent card's context menu:

- **Focus in Kronos task** or **Ask about selection** uses the node as active `follow` context.
- **Use as evidence** attaches it as `quote` context.

The composer displays the selection so you can clear it before submitting. See [Workspace Modes and Canvas](./workspace-canvas).

## Visible execution

KronosCode streams tool activity back into KronTerm. Depending on the surface, you may see:

- active specialist and tool status;
- command and process output;
- code diffs and file previews;
- browser screenshots and structured evidence;
- native or sandbox cursor activity;
- approval requests;
- retry, degraded, failure, verification, and completion state;
- request, decision, action, evidence, approval, and output cards on the canvas.

Do not treat a progress indicator as proof of completion. Review the returned evidence and the final state.

## Files and attachments

Drag files into the composer or use its attachment control. The current compatibility panel accepts common text/code,
image, and PDF inputs. File and provider limits vary.

| Type              | Typical handling                                                           |
| ----------------- | -------------------------------------------------------------------------- |
| Images            | Validated, resized when needed, and sent to models with image capability   |
| PDFs              | Attached to providers with PDF support or prepared for text extraction     |
| Text and code     | Validated, previewed, and attached as readable content                     |
| Large pasted text | Kept as a separate pasted-content item so it remains visible and removable |

Always review attachments and selected canvas context before sending sensitive information to a cloud provider.

## Command-line integration

Use `wsh ai` from a KronTerm terminal:

```bash
git diff | wsh ai -
wsh ai main.go -m "Review this file for race conditions"
wsh ai "$(tail -n 500 server.log)" -m "Find the first failure" -s
```

Use `-n` for a new conversation and `-s` to submit immediately. Without `-s`, the content is added to the composer for
review.

## Models and providers

KronTerm supports provider presets, OpenAI-compatible endpoints, and local model servers. Existing configuration names
such as `waveai.json` and `waveai:*` remain for compatibility.

See [Providers and Local Models](./waveai-modes) for configuration examples. Cloud providers receive the messages,
attachments, and authorized context sent to their API. Ollama, LM Studio, vLLM, or another local endpoint can keep model
inference on your machine.

## Approvals and boundaries

Sensitive actions can pause for approval. The exact confirmation depends on the backend and advertised capability, but
the UI preserves pending requests instead of converting them into ordinary messages.

Keep these distinctions in mind:

- model permission does not grant access to every operating surface;
- sandbox root access does not grant host access;
- structured browser interaction is separate from native desktop control;
- an attached file is model context, while an approved file tool is an execution capability;
- an ACP agent can expose a different capability set from the bundled KronosCode agent.

## Voice, experimental

The microphone control can start the optional local Python engine, capture speech, transcribe it with `faster-whisper`,
and submit the final text through the active composer. Speech output is also supported when an online or offline TTS engine
is available. See [Voice](./voice) for dependencies and privacy details.

## Troubleshooting

### KronosChamber does not load

Read the runtime repair panel. It identifies whether the child process, HTTP health endpoint, credentials, or embedded
client failed and supplies the next recovery action.

### A tool is missing

Tools depend on the selected agent, model, provider, host, and surface. Check the active agent profile, model capability,
MCP configuration, and surface connection.

### A local model cannot use tools

Confirm that its AI mode includes the `tools` capability and that the endpoint implements the required tool-call format.

### Voice is unavailable

Voice requires the optional Python process, its dependencies, a usable microphone, and operating-system permission. The
rest of KronosCode works without it.

KronosCode and KronosChamber are active private-beta features. The voice engine is experimental, and behavior may change
before general release.

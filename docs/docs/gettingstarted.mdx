KronTerm is currently onboarding macOS private-beta users. This guide covers the private-beta build and the common first
steps after launch.

## Get access

1. [Request private-beta access](https://www.kronterm.dev/download).
2. Install the macOS build supplied with your invitation.
3. Complete onboarding and allow only the native permissions required by the surfaces you plan to use.

| Platform                                 | Current status                                       |
| ---------------------------------------- | ---------------------------------------------------- |
| macOS 11 or later, Apple Silicon and x64 | Private beta                                         |
| Windows x64                              | Under evaluation                                     |
| Linux arm64 and x64                      | Under evaluation                                     |
| iPhone                                   | Labs client; see the repository's `mobile/README.md` |

The repository retains upstream package metadata and compatibility code for Windows and Linux. Do not use old Wave
package-manager commands as KronTerm release instructions.

## Create the first workspace

1. Open KronTerm. A new workspace starts with a terminal widget.
2. Add the surfaces the project needs: terminal, browser, preview, editor, KronosChamber, or sandbox.
3. Open **KronSettings → Visual** to select tiled widgets, focused tabs, or the spatial canvas.
4. Open KronosChamber and choose a configured model provider.

KronTerm saves workspace and layout state, so the operating picture can survive an app restart.

## Try the command layer

The `wsh` helper connects terminal commands to the graphical workspace:

```bash
# Preview a local file or directory
wsh view .

# Open a browser widget
wsh web open https://docs.kronterm.dev

# Add terminal output to the AI composer
git diff | wsh ai -
```

`wsh` receives an access token from KronTerm and is intended to run inside a KronTerm terminal or an explicitly connected
session.

## Choose a workspace mode

### Tiled widgets

Drag widget headers to reflow the split layout. Resize neighboring widgets from their shared edge and use <Kbd k="Cmd:m" />
to magnify the focused widget.

### Focused tabs

Use a browser-style tab strip to keep one widget visible in a pane. Drag a tab to another pane or create a split above,
right, below, or left.

### Spatial canvas

Pan and zoom across live widgets. Add notes, shapes, connectors, or freehand marks, then keep agent task and evidence cards
beside the surfaces that produced them. See [Workspace Modes and Canvas](./workspace-canvas).

## Connect KronosCode

KronosChamber is the primary KronosCode chat and control surface. The desktop starts and monitors its local runtime. If the
runtime cannot become healthy, the view shows the failing component and a suggested recovery action.

You can connect OpenAI, Anthropic, Google, OpenAI-compatible services, Ollama, or LM Studio. Cloud providers receive the
context sent to their API; local models can keep inference on the machine. See [Providers and Local Models](./waveai-modes).

## Remote and isolated work

- Use the connection control to open an SSH host. Durable sessions can reconnect after network changes, sleep, or app
  restarts.
- Use Kron Sandbox for package installation, reproductions, and browser or desktop work that should remain isolated from
  the host.
- Keep host, remote, browser, and sandbox actions on their explicit surfaces when directing an agent.

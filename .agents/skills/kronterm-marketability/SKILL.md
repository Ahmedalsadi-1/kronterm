# KronTerm Marketability

Position KronTerm as the persistent workspace where people and agents use terminals, browsers, files, previews, sandboxes, remote systems, and native apps together—not as a bundle of unrelated tools.

## Workflow

1. Name the behavioral persona, job-to-be-done, current workaround, and switching trigger.
2. Validate competitors by substitution behavior. Separate direct competitors from references and adjacent threats.
3. Classify capabilities as table stakes, differentiators, proof points, experiments, or distractions.
4. Select one promise and three evidence-backed pillars. Do not market unreleased or Labs functionality as generally available.
5. Connect the promise to the first-run experience, activation event, retention loop, and measurable outcome.
6. Produce a prioritized change with an owner, acceptance criteria, evidence plan, and explicit non-goals.

## Product thesis

- Native calm: fast, coherent, keyboard-first, and trustworthy.
- Agent control: visible work, approvals, evidence, recovery, and durable sessions.
- Editor leverage: code intelligence, diffs, context, and project navigation.
- Browser intelligence: research and action beside code and terminals.
- Persistent workspace: `widgets`, `tabs`, and `canvas` are presentations of the same durable blocks.

## Guardrails

- Prefer a sharp wedge over “everything for everyone.”
- Do not use feature count as strategy.
- Treat Codex, Cursor, Comet, and Apple products as interaction references, not branding templates.
- Require proof for performance, privacy, security, and autonomy claims.

## Output

Return the target persona, promise, supporting evidence, prioritized improvements, success metrics, risks, and the smallest experiment that could disprove the thesis.
